# Prompt 2 for Antigravity: File import (PDF / Word / text) + "anyone can use it" UX

This is a follow-up to the first prompt (the Medscope Question Sheet Builder). The parser, the A4 pagination engine, the paper styles and the exports already exist. **Do not rewrite them.** This task adds two things:

1. **Import from files**: the user drops a PDF, a Word file or a text file and the tool reads it by itself, instead of copy and paste.
2. **Idiot-proof UX**: assume the person using the site is a tired student who has never seen it, reads nothing, and will click the wrong thing. The tool must still give them a correct PDF.

All processing stays **100% in the browser**. No uploads, no backend, no API calls. Say this on screen ("ملفاتك مابتتبعتش لأي سيرفر").

---

## Part A. File import

### A1. Entry points
- A big **drop zone** that is the first thing on the screen, plus a "اختار ملف" button (`<input type=file multiple accept=".pdf,.docx,.txt,.md,.png,.jpg,.jpeg">`). Dropping files anywhere on the page works too.
- Pasting still works (keep the textarea, but under a "أو الصق النص" section).
- **Multiple files at once** are allowed (e.g. the questions file and a separate answers file, or several subjects). Show each file as a card with name, type, size, status (reading / done / failed), a remove button, and "up/down" to reorder. Order = order of questions in the final sheet.
- Reading happens in a **Web Worker** so the page never freezes. Show a progress bar per file (for PDFs: "صفحة 12 من 46").
- Files are read into the same pipeline as pasted text: `file → extractText() → text with ✓ markers → parse()`. The existing `parse()` stays the single source of truth.

### A2. Supported types
| Type | How |
|---|---|
| **.txt / .md / .csv** | `FileReader.readAsText`, detect UTF-8 vs UTF-16 BOM, normalise line endings. |
| **.docx** | Unzip with **fflate** or **JSZip** and read `word/document.xml` yourself (do NOT rely on Mammoth alone, it drops colour). See A3. |
| **.pdf (with text layer)** | **pdfjs-dist** (lazy-load it, set `workerSrc` properly for Vite). See A4. |
| **.pdf scanned / images (.png .jpg)** | Offer **tesseract.js** OCR (English), lazy-loaded only when needed, with a clear "ده بياخد وقت" warning and progress. |
| **.doc (old Word)** | Not supported: show a friendly message "الملف ده بصيغة Word قديمة. افتحه في Word واحفظه كـ .docx وارفعه تاني." |
| anything else | Friendly message listing what is supported. Never a raw error. |

### A3. Word (.docx) extraction details
Walk `w:body` in order: `w:p` paragraphs and `w:tbl` tables (flatten each table row into lines; cells separated by two spaces). Ignore headers/footers, comments, footnotes, text boxes are optional.
- For every paragraph build the line from its `w:r` runs (`w:t`, `w:tab` -> space, `w:br` -> new line).
- **Colour**: read `w:rPr/w:color@w:val`. A run is "red" when r>=150, g<=95, b<=95 (e.g. `C00000`, `FF0000`). Also honour `w:highlight` (yellow/green) as an optional "highlight means correct" mode and **bold** as an optional mode (setting: "اعتبر الخط العريض إجابة صح", default OFF, because Medscope stems are bold).
- If more than 60% of the visible characters of a paragraph are red, append ` ✓` to the line. This is the same convention the clipboard-paste code already uses.
- **Word auto-numbering**: questions and options are often real Word lists, so the digits/letters are NOT in the text. Read `w:numPr` (numId, ilvl) and the numbering definitions (`word/numbering.xml`: `w:numFmt` decimal / lowerLetter / upperLetter / lowerRoman, `w:lvlText` like `%1.`, `%2)`), keep a counter per (numId, ilvl) that resets correctly when a higher level restarts, and **prefix the generated label** ("12. ", "c) ") to the line text. Verify with a document that uses auto-numbered lists.
- Smart quotes, non-breaking spaces, soft hyphens, zero-width characters: normalise.
- Embedded images: ignore, but if the document has images and the parser finds zero questions, tell the user "الملف فيه صور بس، جرّب ترفع الصفحات كصور للـ OCR".

### A4. PDF extraction details
Use `pdfjs.getDocument` and for every page `getTextContent()`.
- Rebuild **lines** by grouping text items with the same baseline (`transform[5]` within ~2-3 units), sorting by `transform[4]` (x). Insert a space when the gap between items is larger than ~0.25 of the font height. Insert a blank line when the vertical gap is larger than ~1.6x the line height. Handle **two-column pages** (detect when items split into two x-clusters and read the left column first).
- Remove obvious repeated headers/footers (same text at the same y on >=60% of pages) before returning text. (The parser also removes lines repeated 3+ times, keep both.)
- **Red answers in PDFs (important)**: `getTextContent()` does not give colour. Run `page.getOperatorList()` and track the current fill colour through `setFillRGBColor`, `setFillColor`, `setFillGray`, `setFillCMYKColor`, `save`/`restore`, and map it to each `showText` operation, so every text chunk gets an RGB value. Match chunks to the lines above (by position or by walking both lists in order). Apply the same ">60% red -> append ` ✓`" rule. Test on `Medscope_End_As_30.pdf`: it has red correct options and the text layer is otherwise identical to the questions-only file.
- If a page yields almost no text (<20 characters) on most pages, it is scanned: offer OCR, do not silently fail.
- Password-protected PDF: friendly message ("الملف عليه باسورد").

### A5. Smart merging when the user gives 2 files
- **Same questions twice** (like `Qs.pdf` and `As.pdf`): detect by comparing the normalised stems (>=80% identical, same count). Use the file that has answers as the answer source and the other as the layout source. Never duplicate the questions. Tell the user what you did: "لقيت إن الملفين نفس الأسئلة، واخدت الإجابات من الملف التاني".
- **Questions file + key file** (a file with no options but many `1-B` pairs, or a filename containing `answer`, `key`, `As`, `اجابات`): feed it to the existing answer-key logic.
- **Different subjects in several files**: append in the order shown on screen, one section per file name if the file has no headings (use the file name as the subject name, cleaned: `Physiology_Qs.pdf` -> `Physiology`).

### A6. After reading, always show a "what I found" report before anything else
A friendly summary card, e.g.:
> قرينا **3 ملفات** ✓  
> لقينا **227 سؤال** في **17 مادة**  
> **227 سؤال له إجابة** ✓  (من الأحمر في الملف / من مفتاح الإجابات)  
> 2 سؤال محتاجين مراجعة ⚠ [راجعهم]

Every number is a button that jumps to the matching list in the editor.

## Part B. Make it impossible to get wrong

### B1. Flow: 3 big steps, one screen each, always visible at the top
`١ ضيف الأسئلة  →  ٢ راجع  →  ٣ نزّل الـ PDF`. The next step button is big and gold and says what will happen ("كمّل: راجع الأسئلة"). The user can go back at any time without losing anything. Default view is Step 1 with only the drop zone and the paste box. **Hide advanced settings** behind a single "إعدادات متقدمة" accordion. The defaults must already produce a beautiful sheet.

### B2. Step 3 is one decision
Two huge buttons: **"نزّل ورقة الأسئلة (PDF)"** and **"نزّل ورقة الإجابات (PDF)"**, plus "نزّل الاتنين". Explain once, in plain words, what happens when the browser print window opens: "هيفتح لك شاشة الطباعة. اختار **Save as PDF**، وفعّل **Background graphics**". Show a small annotated screenshot or illustration of that window. If possible, avoid the print dialog entirely by generating the PDF directly (e.g. `html2canvas` + `jsPDF`, or `pdf-lib` with vector text) as an alternative "تحميل مباشر" button; keep the print route as the fallback. Whichever you choose, the PDF must keep selectable text and the A4 page breaks shown on screen.

### B3. Forgiving input (the parser must survive messy human input)
Add these on top of the existing rules and unit-test each one:
- Arabic-Indic digits (`١٢٣`) and Arabic letters as option labels (`أ) ب) ج) د)`) are converted to `1 2 3` and `a b c d`.
- `a )`, `a)text`, `a.text`, `A-`, `(A)`, `a/`, `[a]`, options with a missing space, options glued to the stem line.
- `1/`, `1 -`, `1 )`, `Q 1`, `Question No. 1`, `س1`, `س 1:`.
- Extra blank lines, tabs, trailing spaces, mixed line endings, text pasted with every line double-spaced.
- Answers written as `Ans: B`, `Answer = b`, `الإجابة: ب`, `✔`, `✅`, `(correct)`, `*`, **bold/red in rich paste**.
- Two answers marked on one question: do not choose silently. Flag it as a problem.
- A question with only one option, or the stem missing: flag it, keep the text, let the user fix it.
- Numbers not starting at 1, gaps in numbering, repeated numbers: accept, never crash, renumber on output.
- Very large input (1000+ questions): stays responsive (parse in a worker, paginate in chunks, virtualise the on-screen pages).

### B4. The "Problems" panel (Step 2)
Instead of hoping the user notices, list every problem in plain Arabic with a one-click fix and a "jump to question" link:
- "سؤال 14 مفيهوش إجابة صح" -> inline choice buttons a/b/c/d to pick it right there.
- "سؤال 22 ليه إجابتين" -> pick one.
- "سؤال 31 فيه خيار واحد بس" -> edit.
- "سؤال 8 مكرر مع سؤال 40" -> keep / delete.
- "كل الإجابات a تقريبًا" -> a hint, not a blocker.
- "في سطور ما عرفتش أحطها فين" -> show the unparsed lines with a button "ضيفها للسؤال اللي قبلها" / "اعتبرها سؤال جديد" / "تجاهلها".
Nothing blocks the download. Problems are warnings; the user can always continue ("كمّل برضه").

### B5. If nothing was understood
When 0 questions are found, never show an empty screen. Show: "ما لقيتش أسئلة في الملف ده 😕" + the 3 most likely reasons (scanned PDF, no option letters, Word list numbering) + a **"شوف مثال على الشكل المقبول"** + "جرّب بمثال" + "أضيف الأسئلة بإيدي" (opens the editor with one empty question). Include a visible "ابعتلنا الملف" instruction only as text (no upload).

### B5b. Never lose work
- Autosave everything (text, settings, edits, file contents as text) to localStorage/IndexedDB; on reopening show "رجّع آخر شغل" with date and question count.
- Destructive actions ("مسح الكل", delete subject, replace content) ask for confirmation **inside the page** (no `confirm()`) and offer **Undo** for 10 seconds via a toast.
- `beforeunload` warning only if there are unsaved manual edits.

### B6. Plain words and big targets
- No technical words anywhere on screen (no "parse", "regex", "TSV", "JSON" in the main flow; exports live under a "حفظ بصيغ تانية" section with one-line human explanations: "Anki: للمراجعة بالكروت").
- Every control has a short Arabic label, and anything unclear has a "؟" tooltip that works on touch.
- Buttons at least 44px high, high contrast, visible keyboard focus, works on a phone (many students will use one), and RTL is correct.
- Success feedback after every action ("اتضافت 60 سؤال ✓").
- A tiny first-visit tour (3 steps, skippable, never shown again) and a **"إزاي أستخدم الموقع؟" 30 second help** button that opens an illustrated panel.
- The most common mistake must be handled: the user uploads the **answers file as the questions file**. Detect it (red/✓ marks present on most questions) and say "الملف ده فيه الإجابات كمان، هستخدمها" instead of treating it as an error.

9. 1000-question file -> UI stays responsive, parse < 2 s, first page rendered < 1 s.
10. Everything works with the network off after first load (lazy chunks for pdf.js / tesseract are cached by a service worker or bundled locally, no CDN dependency at runtime).
11. Keyboard-only run through all 3 steps; phone-width layout (390px) usable.

## Part D. Rules
- Reuse existing modules. New code goes in `src/import/` (`readTxt.js`, `readDocx.js`, `readPdf.js`, `ocr.js`, `merge.js`, `worker.js`) with unit tests where DOM is not required.
- Lazy-load heavy libraries (pdf.js, tesseract.js) so the first load stays fast.
- No external requests at runtime, no analytics, no uploads.
